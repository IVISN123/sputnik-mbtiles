# Спутник — MBTiles

Браузерное приложение: отмечаете круг на карте, оно скачивает только те спутниковые тайлы, которые этот круг пересекает, и собирает файл `.mbtiles` прямо на вашем компьютере. Сервера у приложения нет. Ключи MapTiler и Mapbox остаются в `localStorage`.

Собрано для офлайн-карт наземных станций: QGroundControl, Mission Planner и Android-станции (в том числе пульты вроде G12).

Сайт: <https://ivisn123.github.io/sputnik-mbtiles/>

Чтобы сайт открылся, в настройках репозитория GitHub нужно один раз включить Pages и выбрать источник **GitHub Actions**.

## Как пользоваться

1. Откройте сайт (или `npm run dev` и адрес `/sputnik-mbtiles/`).
2. Выберите источник снимка. Для сборки из браузера обычно подходит **Esri World Imagery**: он чаще других отдаёт CORS.
3. Кликните по карте, вставьте координаты (десятичные или DMS) или нажмите «Моё положение».
4. Задайте радиус и диапазон масштабов. Круг на карте и оценка числа тайлов обновляются сразу. Большой объём (больше 20 000 тайлов или оценка больше 1 ГБ) только предупреждает — кнопка сборки остаётся доступной.
5. Нажмите «Собрать файл». Можно поставить на паузу или отменить. Битые тайлы пропускаются, отчёт можно скачать.
6. Браузер сохранит `.mbtiles`. Если включены галочки — ещё `.qgctiledb` и ZIP.

Подложка OpenStreetMap нужна только чтобы найти место. В файл она не попадает.

Последние настройки, включая ключи, запоминаются в этом браузере. Кнопка «Забыть ключи API» стирает только ключи.

## QGroundControl

Текущий стабильный QGroundControl **не открывает** обычный MBTiles. Он импортирует свой SQLite-файл `.qgctiledb`. Приложение умеет собрать его вместе с MBTiles (галочка включена по умолчанию).

Хэш тайла в этом файле — это номер слота карты в QGC, X, Y (схема XYZ, не TMS) и масштаб, в том виде, как QGC ищет тайл в кэше. После импорта в станции нужно выбрать **тот же тип карты**, под который собран файл. Для снимка Esri это **Esri World Satellite**. Если сборка QGC собрана с `QGC_NO_GOOGLE_MAPS`, включите соответствующую галочку: номера слотов в такой сборке сдвинуты.

Импорт:

1. Q → Application Settings → Maps (или Offline Maps) → **Import**.
2. Укажите файл `.qgctiledb`. Допишите набор к уже существующему кэшу, не затирайте его, если там есть другие районы.
3. Выберите тип карты, совпадающий со слотом (Esri World Satellite, Google Satellite, Bing Satellite или Mapbox Satellite).
4. На Android файл кладут туда, откуда диалог импорта его видит. Часто это каталог `QGroundControl/Missions` во внутренней памяти. Само окно импорта показывает путь.

Номера слотов сняты с ветки `master` QGC на момент сборки этого приложения. Если в вашей версии список провайдеров другой, снимок импортируется, но не появится на экране, пока хэш не совпадёт с выбранным типом карты.

## Mission Planner

Mission Planner не открывает `.mbtiles` как карту. Его кэш — это каталог JPEG.

1. При сборке выберите ZIP с раскладкой **Mission Planner: Custom/z/y/x.jpg**.
2. Распакуйте так, чтобы файлы легли в кэш:
   - Windows: `C:\ProgramData\Mission Planner\gmapcache\TileDBv3\en\Custom\<z>\<y>\<x>.jpg`
   - Linux: `~/.local/share/Mission Planner/gmapcache/TileDBv3/en/Custom/<z>/<y>/<x>.jpg`
3. Каталог языка (`en`) должен совпасть с тем, что уже есть в `TileDBv3`. Если там другое имя, кладите файлы в него.
4. На экране Plan выберите карту **Custom**.

Путь именно `z/y/x.jpg`: так файл ищет кэш Mission Planner (`MyImageCache`). Координата Y здесь обычная XYZ, не перевёрнутая TMS. Чтение идёт по расширению `.jpg`, даже если внутри PNG.

Если рядом с Mission Planner установлен GDAL, MBTiles можно подключить как растровый слой отдельно от этого кэша.

## Android GCS и пульт G12

Файл `.mbtiles` — обычный растровый MBTiles 1.1: Web Mercator (EPSG:3857), JPEG или PNG, в таблице `tiles` строка тайла хранится в схеме TMS. Так его читают QGIS, OsmAnd и типичные Android-библиотеки вроде osmdroid.

1. Скопируйте `.mbtiles` на устройство: кабель, карта памяти или отправка файла себе.
2. В приложении станции откройте офлайн-карты или слои и импортируйте MBTiles.
3. Если приложение ждёт не базу, а каталог тайлов, распакуйте ZIP в раскладке **XYZ: z/x/y** туда, откуда оно читает кэш.

У разных прошивок пультов G12 пункт меню называется по-разному. Формат файла при этом один и тот же.

## Источники и CORS

Тайл для карты браузер показывает через тег `img`, и CORS ему не мешает. Чтобы положить байты в SQLite, скрипт должен **прочитать** ответ. Если сервер не разрешает чтение с чужого сайта, сборка невозможна. Приложение это определяет (пробный запрос и остановка, если первые тайлы падают сетью) и пишет, в чём дело.

Сторонний прокси не используется и не предлагается. Обход CORS — это уже ваш сервер: его можно указать своим шаблоном `https://…/{z}/{x}/{y}.jpg`.

| Источник | Что ожидать |
| --- | --- |
| Esri World Imagery | Чаще всего читается из браузера |
| Google Satellite | Карта видна, чтение тайлов обычно закрыто CORS. Условия Google, как правило, запрещают массовое сохранение |
| Bing Aerial | Запрос идёт quadkey-адресом. CORS обычно закрыт |
| MapTiler / Mapbox | Нужен свой ключ. Он хранится только в `localStorage` |
| Свой XYZ | `{z}` `{x}` `{y}` `{-y}` `{quadkey}` `{s}` `{key}` |
| Яндекс Спутник | Не предлагается. См. ниже |

Вы сами отвечаете за условия выбранного провайдера. Приложение только формирует запросы, которые сделал бы браузер.

### Почему нет Яндекса

Тайлы Яндекс Спутника нарезаны в эллиптическом Меркаторе **EPSG:3395**. MBTiles и наземные станции читают тайлы как сферический Web Mercator **EPSG:3857**. Если положить яндексовский тайл в ту же ячейку z/x/y, снимок встанет со сдвигом, и чем севернее, тем сильнее. Честное исправление — перепроецировать каждый пиксель. Этого приложение не делает, поэтому источник исключён, а не «почти работает».

## Ограничения

- Жёсткого лимита на число тайлов нет. Свыше 20 000 тайлов или при оценке больше 1 ГБ интерфейс предупреждает, но сборку не запрещает. Для очень большого круга живая цифра — оценка по площади; точный обход делается уже по кнопке.
- Тайл записывается в SQLite сразу после скачивания и не копится вторым массивом байтов. Журнал SQLite выключен, чтобы свежие страницы не лежали в памяти дважды. В момент сохранения файла sql.js всё же делает одну копию базы. `.qgctiledb` и ZIP, если они включены, собираются после загрузки, по одному тайлу, а не из полного списка картинок.
- В файл попадают только тайлы, чья ячейка пересекает круг, а не весь описанный прямоугольник.
- Одновременно качается 4 тайла, с повтором и паузой на 429 и 5xx. 404 и отказ сервера не долбятся. Ошибки пропускаются, в файл их нет.
- WebP, если источник его отдал, перекодируется в JPEG: часть станций WebP не показывает.
- Оценка размера — ориентир (~30 КБ на тайл), не обещание.
- Снимки провайдера могут быть старыми и со смещением относительно съёмки, по которой вы летали. Перед выездом сверьте один-два ориентира.

## Формат MBTiles

SQLite, спецификация MBTiles 1.1:

- таблица `metadata`: `name`, `format` (`jpg` или `png`), `bounds` (запад, юг, восток, север), `center`, `minzoom`, `maxzoom`, `type=baselayer`, `attribution`, `description`, `version=1.1`, `scheme=tms`;
- таблица `tiles`: `zoom_level`, `tile_column`, `tile_row`, `tile_data`;
- `tile_row` — строка TMS: `(2^z - 1) - y` от обычной XYZ;
- уникальный индекс `tile_index` по `(zoom_level, tile_column, tile_row)`.

## Разработка

Нужен Node.js 22.

```bash
npm ci
npm test
npm run dev
npm run build
```

Тесты покрывают перевод круга в тайлы (включая антимеридиан и отказ от огромной области), переворот TMS, quadkey, разбор координат, адреса Esri/Bing и запись MBTiles и `.qgctiledb`.

Сборка кладётся в `dist/` с базовым путём `/sputnik-mbtiles/`. GitHub Actions на каждый push и pull request гоняет тесты и сборку. Публикация на Pages выполняется только с ветки `main`, и только если в репозитории Pages включены с источником **GitHub Actions**.

Код приложения можно использовать свободно. Снимки в скачанных файлах остаются под условиями того провайдера, у которого вы их запросили.
